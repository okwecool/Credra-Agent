| 模型 | 总调用 ID、PROCESS/STRUCTURED 各 attempt、首 Token/耗时/usage、HTTP 请求信息、JSON/Schema/引用/业务校验和降级；不输出原始内容 |
| 工具/持久化 | 搜索/抓取/核验、MCP 会话/工具结果、SQLite 读写、Artifact、报告、审计导出 |
| 故障恢复 | 节点开始前确认日志健康；故障节点边界持久化于旧 SQLite，状态接口投影 execution_blocked；CLI/Chainlit 的 resume_logging 只恢复这个安全边界 |
| 配置与使用 | `.env.example` 提供默认配置；`logs/` 忽略；用户 `.env` 未改；使用方法见[全服务日志使用说明](全服务日志使用说明.md) |

具体适配记录：

1. 依赖保持原版本。确认安装的 SqliteSaver.from_conn_string 使用 cls 构造实例后，通过子类观察 get_tuple/put/put_writes，不修改 Checkpoint 内容。
2. FastMCP StdioTransport 默认 keep_alive=True。日志宿主可能变化，因此有活动服务上下文时为每次会话创建 keep_alive=False 的传输，使用当时的端点；原查询参数/结果语义保留。
3. MCP 工具增加可选诊断上下文；子进程返回 `_service_log_available` 技术字段，客户端消费后移除，再验证原 ResearchQueryResult。子日志失败使父服务暂停后续节点，业务结果继续保存，不作为工具失败重试。
4. TraceEvent 拒绝新增字段，继续采用任务/行号引用桥接；不改旧 Trace JSON Schema。读取行号并追加写入使用进程内锁，跨进程 Trace 写入并发仍沿用旧系统边界。
5. HTTP 响应头的 x-request-id 才用作请求 ID，completion ID 不替代；缺少响应/usage 时保留未知。SDK 日志不格式化原 msg/args/exc_info，异常保留受限位置引用。
6. baseline 的可恢复执行单位是节点，日志故障让当前节点按既有有界逻辑保存结果，在下一节点前暂停。P14 才增加逐 Action/请求账本；没有把中途外调终止冒充安全的日志恢复。

## P10/P11 实现与适配

| TaskSpec 生产契约 | `credra_agent/intent` 提供期间、来源策略、问题、条件、不可变版本快照和解析结果；READY 必须绑定已导入 Case，歧义进入 NEEDS_CLARIFICATION |

| 自然语言语义 | 固定 `as_of`，识别显式年度、现金质量/回款/担保等重点、来源优先/仅限/禁止、条件动作、状态/暂停/恢复/报告批准；审核绕过和“无材料即无风险”被拒绝 |
| 持久化与去重 | 与 Checkpoint 共库、独立 `credra_intent_messages` 表；按 `source_message_id` 幂等，TaskSpec 版本单调，跨 Thread 复用消息 ID 拒绝；澄清快照和控制命令均绑定持久化版本 |
| CLI/Chainlit | 新增 `app.task_cli parse`；Chainlit 非命令文本进入自然语言解析并展示主体、截止日、期间、重点、版本及待澄清项。P12 前明确显示不会自动发起外部调用 |
| Action 注册表 | `credra_agent/execution` 注册九类工具的专属参数 Schema 与可用性；全部声明只读，`compare_peers`、`run_scenario` 明确 UNAVAILABLE，不能因模型选择而假装执行 |
| 完整 MCP 查询 | 新 `search_evidence` 接收 query、主体 ID/名称、日期范围、来源策略和类别；客户端、FastMCP 服务端和 Provider 使用同一个验证对象，Provider 不再按旧类别后缀重建 query |
| 兼容 | 旧 `search_company`/`search_industry` 继续生成原模板；旧 SearchRequest 新字段均可空。Snapshot key 对 legacy 请求排除新增空字段，保持原哈希；带 V2 约束的请求以约束区分快照 |

生产 TaskSpec 将控制命令与任务快照分开：`start/amend` 生成 TaskSpec，`status/pause/resume/approve_report` 只绑定既有版本。V2-0 原型把 operation 放在单个 TaskSpec 中，无法表达“短控制指令不重建任务”；这是按架构第 4.1/4.3 节所做的生产适配，原型和冻结 fixture 未被改写。

当前控制命令状态为 `CONTROL_PENDING`，只完成解析、绑定与持久化，不接管 legacy 审核/恢复路径。P12–P14 将增加 Coordinator、Policy、预算预留和版本化 Action 账本后，才允许自然语言 TaskSpec 派发工具；因此本节点不宣称 A11/A12/A14/A15 已通过。

## 范围与后续

本次交付包含自然语言解析与 TaskSpec 持久化、Action Schema 注册表及完整搜索参数通道，不包含 Coordinator 自动派发、动态预算、执行账本或新真实案例。原 Case source 和人工答案未修改；用户 `.env` 未修改。

`resume_logging` 仅恢复 SQLite 中明确的节点前日志门禁失败。没有安全标记、请求结果不确定、数据损坏时拒绝该恢复入口；日志不是第二份业务状态。ACK 丢失和内存去重窗口不构成 exactly-once，断电/硬件损坏不承诺无损。

下一节点为 P12 Coordinator，并与 P13 的执行门禁/预算约束协同设计，随后完成 P14 版本化恢复。D05 真实调用预算仍未确认，禁止未获授权的付费试跑；D04 真实案例选择留待 V2-2。
