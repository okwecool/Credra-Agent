## 2. 数据与信任边界

生产模块位于 `credra_agent/evidence/`。版本为 `evidence_bundle_v2_p21`，与 P02 Spike 原型分开，不覆盖旧契约或 JSON。

| 对象 | 表达与约束 |
|---|---|
| Entity / EntityRelationship | 法人名称、明确别名和稳定 ID；完整名称匹配，别名碰撞留作歧义。子公司/同名关系必须引用单独的实体关系事实主张和采信证据、带核验版本；关联关系不产生主张继承 |
| Document | 原始来源/发布者与承载者分开；发布日期、事件日/窗口、报告期间、带时区的获取时间分开。未知值保持 null；RESPONSE_BYTES 与 EXTRACTED_TEXT 哈希明确区分；原文 fragment 与仅供定位的 hint 分开 |
| EvidenceDraft | 非可信的主体/关系/片段提案；禁止输入 ACCEPTED 或 verifier_version。模型规划输出本身不能产生采信回执 |
| Evidence | 文档/主张/主体引用、支持/反证、片段和位置、关系核验版本、主体范围核验版本、主张级 origin_group、显式修订关系与限制 |
| Claim | 事实主张、当事方声明、分析估计、系统推断和假设分别标记；声明/估计需归属，推断需理由；状态及引用由有效证据投影，支持和反证同时存在时必须保留 CONFLICTING |
| Corroboration | 单独的语义独立性核验记录与理由；网站数/类别数/不同内容哈希不能自动生成独立印证 |

`accept_evidence` 是可信核验服务的入口，要求调用方提供独立的主体范围核验回执。它校验文档和主张 ID、主体相同、已分类且带哈希的文档、发布/获取日期，以及原文片段能在指定页段中定位。服务对语义判断的正确性仍依赖对应版本核验器；片段包含关系不是自动事实判定，也不以字符串版本号证明来源真实性。当前旧调查路径没有此主体范围回执，不能直接升级采信。

`EvidenceBundle` 在创建和持久化时校验整个引用图：重复/缺失 ID、非法主体引用、文档哈希不符、真实/合成/未知材料混用到同一主张、原文位置不符、主张状态与证据不符均拒绝。文本哈希校验重新计算全部 fragment 文本；原始响应字节哈希来自 P20 获取回执，不由文本抽取值冒充。该哈希标识内容，不保证材料真实性。

## 3. 时间、同源与修订

- 有效证据需发布日期已知且不晚于 as_of；已知事件/窗口与报告期间不越过截止日。获取时间允许晚于截止日，不能用抓取日替代发布/事件日。事后获取不等于截止日前已归档；动态页面没有历史版本证明时，仍需核验器披露限制。
- 物理页与印刷页分别存储，`page:N` 与显式物理页必须一致；正文位置必须精确指向对应 fragment。旧清单的字段定位只映射成 hint，不能补造原文。
- Evidence 的 origin_group 是主张级依赖，不是对整篇文章所有主张的统一裁决。相同原始来源/主张来源组归并，但保留转载证据历史；相同范围的内容哈希另列重复文档。来源未知时不能按不同域名补造独立来源。
- 独立印证需明确核验记录；引用必须是同一主张当前有效的支持证据，原始依赖组、原始发布者和文档内容须分别可区分。公司声明和媒体报道同一声明可以证明“有该声明”，不能由此证明承诺已履行。
- 文档修订链要求同原始来源、发布者、材料类型且日期不倒退；拒绝环和缺失节点。证据只在显式指向同一主张的已核验文档修订时退休旧版本。每年新年报不会自动替换整份旧年报；字段重述继续由 P24 处理。截止日之后的修订不能退休截止日前有效版本。

P20 导入仅形成 16 份 Document 元数据和主张来源组线索，没有 Evidence、实体关联认定或已采信事实。事件/参考窗口按目录原范围保留，不猜单个事件日。监管汇总涉及的“比亚迪汽车工业有限公司”与“比亚迪股份有限公司”保持两个实体；目前没有录入已核验关联证据，母公司适用范围继续待查。

## 4. 兼容映射与实际接入

| 旧数据 | P21 行为 |
|---|---|
| source_manifest | 保留标题/链接/声明发布者/发布日期/期间标签/页码定位；清单 accessed_at 不作为逐文档获取时间；原始发布者、哈希、原文和事件未知时不填造；只形成元数据 |
| ResearchEvidence + ClaimVerification | 保留旧核验版本、片段/位置；可通过注入的本地 snapshot loader 核对 URL、最终 URL、文本哈希和原文；缺缓存或身份/哈希改变保留限制，不重新外调 |
| 只有 Fact 或整体 SUPPORTED/CORROBORATED | 形成未验证假设，不补造 Evidence；旧接受标记没有断言主体范围和来源依赖信息，V2 仍为 PENDING/UNVERIFIED |
| 旧路径 baseline | 旧搜索、核验、规则、Case 数据及原返回 Schema 不变；P21 侧车只在 agentic 的可信执行路径创建 |

`build_agentic_executor` 保留原始 ResearchQueryResult payload，同时生成类型化 `ExecutionOutcome.evidence_bundle`。默认源类型为 UNKNOWN、没有本地 loader；需要可信调用方显式注入材料类型和离线读取服务，不根据 Provider 名称猜“真实”。映射异常保留已返回外部结果、已发生请求计数及问题缺口，不使结果变成可自动重试的请求。

独立 Coordinator 和生产 Graph 共用 `write_evidence_artifacts`：

1. 原始服务结果保存在 `agent_tool_result_vN.json`。
2. 类型化证据图保存在 `agent_evidence_vN.json`。
3. 主张、证据图引用、规范 JSON 哈希及结构化观察摘要保存在 `agent_claims_vN.json`。
4. 既有 `agent_observation_vN.json` 引用上述 Artifact，Graph/Checkpoint 仍只保存引用。

证据图必须匹配动作任务的主体和 as_of。生产 Graph 的 RESULT_STORED 恢复先验证证据图、主张侧车、链接和哈希；缺失/损坏时停止为 LIMITED / EVIDENCE_ARTIFACT_INVALID，不再次派发工具或模型。该摘要哈希用于检测落盘不一致，不是抵御可同时修改全部本地文件者的签名。

**一项行为修正：** V2-1 搜索 Adapter 曾把整体 SUPPORTED/CORROBORATED 直接映射到 matching_questions 已回答。P21 发现这允许仅有旧摘要而没有原文、主体范围回执的结果绕过完成门禁，因此不再自动回答问题，保持 gap。Claim 的 SUPPORTED 也不是用户问题的完成判定；P22 将读取证据状态、冲突与缺口，在语义核验和 Completion 门禁之后回答或披露停止。本轮不把该路径暂时只能形成受限调查解释成最终 Agent 已完成。

Artifact 写入/读取沿用已有服务日志挂点与动作上下文；不将正文、查询自由文本或真实 Key 输出到服务日志。
