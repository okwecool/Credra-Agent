# Credra Agent MVP 演示指南

本指南用于按固定顺序展示 MVP 的四条关键能力。所有命令均从仓库根目录执行。

## 演示前准备

```powershell
conda activate env_agent
python -m pip check
```

每次演示使用新的 `thread_id`，避免与已有 SQLite Checkpoint 冲突。

## Demo 1：正常Case

```powershell
python -m app.task_cli start `
  --thread-id showcase-normal-001 `
  --case-id case_normal
```

观察点：

- 任务直接 `COMPLETED`；
- `risk_level=LOW`；
- 没有 Research MCP 调用；
- 没有 interrupt；
- 生成 `data/case_normal/output/credit_report.md`。

## Demo 2：风险Case与动态路径

```powershell
python -m app.task_cli start `
  --thread-id showcase-risky-001 `
  --case-id case_risky
```

观察点：

- 异常标记包含现金流背离和负债率上升；
- Research MCP Server 自动启动；
- Risk evidence 包含 MCP `source_id`；
- 任务停在 `WAITING_APPROVAL`。

## Demo 3：完全重启后的Resume

关闭启动任务的终端，打开新终端：

```powershell
conda activate env_agent
python -m app.task_cli status --thread-id showcase-risky-001
python -m app.task_cli resume `
  --thread-id showcase-risky-001 `
  --decision approve `
  --comment "跨进程恢复演示通过。"
```

观察点：

- 不需要再次输入 `case_id`；
- Checkpoint 恢复 Artifact Reference 和待处理 interrupt；
- 最终报告包含人工意见；
- 状态进入 `COMPLETED`。

## Demo 4：Fail-first Retry与Trace

```powershell
$env:RESEARCH_FAIL_FIRST="1"
$env:MAX_RETRY="2"

python -m app.task_cli start `
  --thread-id showcase-retry-001 `
  --case-id case_risky

Get-Content traces/showcase-retry-001.jsonl
```

观察点：

- `search_company` 首次失败后成功；
- `search_industry` 首次失败后成功；
- Trace 分别包含 `RETRY` 和成功 `TOOL_CALL`；
- 任务仍正常进入人工审核。

清理当前终端变量：

```powershell
Remove-Item Env:RESEARCH_FAIL_FIRST
Remove-Item Env:MAX_RETRY
```

python -m app.task_cli resume `

## M0：真实公开 Case 验收（比亚迪 002594）

本节验证 `case_byd_002594`：基于用户授权保存的公开年报和企业公开资料，完成“真实输入 → 财务计算 → 风险/HITL → 可追溯产物”的本地闭环。它不调用实时互联网搜索，也不调用真实 LLM；实时搜索与事实核查属于后续 M2 阶段。

### 1. 完整回归门禁

为避免 Windows 下 Conda 环境在子 PowerShell 中回退到 base，显式指定 `env_agent` 的解释器：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify.ps1 `
  -PythonExecutable "E:\Environment\Anaconda3\envs\env_agent\python.exe"
```

预期：Ruff、pytest、依赖一致性检查和独立 MCP stdio smoke 均通过。`traceloop` 传递依赖的 Pydantic 弃用警告不影响本项目验证结果。

### 2. 启动真实 Case

```powershell
$threadId = "byd-m0-$(Get-Date -Format 'yyyyMMdd-HHmmss')"

python -m app.task_cli start `
  --thread-id $threadId `
  --case-id case_byd_002594
```

观察点：

- Financial 路由异常标记为空，因此路径从 `financial` 进入 `risk`，不调用本地 Mock Research MCP；
- Risk 层仍会因经营现金流较 2023 年下降、期末流动比率低于 1 给出 `risk_level=HIGH`；
- 任务停在 `WAITING_APPROVAL`，等待人工审核。这说明“路由异常规则”与“风险规则”目前是两套不同的确定性规则，属于 M0 已记录的基线行为。

### 3. 审核、恢复并检查产物

```powershell
python -m app.task_cli status --thread-id $threadId

python -m app.task_cli resume `
  --thread-id $threadId `
  --decision approve `
  --comment "已人工核对比亚迪公开年报数据，继续生成报告。"

python -m app.task_cli status --thread-id $threadId
```

预期最终状态为 `COMPLETED`。检查运行产物：

```powershell
Get-ChildItem .\data\case_byd_002594\artifacts\
Get-Content .\data\case_byd_002594\output\credit_report.md
```

其中 `source/source_manifest.json` 可用于人工回溯公开 URL、年报页码、单位和字段口径；运行时生成的 Artifact、报告、Checkpoint 和 Trace 均由 Git 忽略。

### 4. 可选：快速离线预览

该命令不会验证 Durable Runtime、Checkpoint 或人工审核，只生成一份确定性预览报告：

```powershell
python -m app.main .\data\case_byd_002594 `
  --output .\data\case_byd_002594\output\byd_m0_preview.md
```

## M1：新 Case 导入前校验

在运行真实 Case 前，推荐先执行：

```powershell
python -m app.case_cli validate --case-id case_byd_002594
```

比亚迪 M0 Case 的预期结果为 `status=VALID`、`normalized_currency=CNY_1000`、`errors=[]`。新建资料模板：

```powershell
python -m app.case_cli init --case-id case_my_company
```

填写 `data/case_my_company/source/` 中的四个文件后，使用 `validate` 检查；只有校验通过才使用 `run` 启动 Durable Runtime：

```powershell
python -m app.case_cli run `
  --case-id case_my_company `
  --thread-id my-company-001
```

`run` 在校验失败时不创建任务 Checkpoint。第一版只接收人工结构化的公开年报数据，不把 PDF/OCR 解析设为运行门槛。
