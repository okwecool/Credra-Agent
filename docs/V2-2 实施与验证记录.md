### 2. 数据与信任边界

生产模块位于 `credra_agent/evidence/`。版本为 `evidence_bundle_v2_p21`，与 P02 Spike 原型分开，不覆盖旧契约或 JSON。

| 对象 | 表达与约束 |
|---|---|
| Entity / EntityRelationship | 法人名称、明确别名和稳定 ID；完整名称匹配，别名碰撞留作歧义。子公司/同名关系必须引用单独的实体关系事实主张和采信证据、带核验版本；关联关系不产生主张继承 |
| Document | 原始来源/发布者与承载者分开；发布日期、事件日/窗口、报告期间、带时区的获取时间分开。未知值保持 null；RESPONSE_BYTES 与 EXTRACTED_TEXT 哈希明确区分；原文 fragment 与仅供定位的 hint 分开 |
| EvidenceDraft | 非可信的主体/关系/片段提案；禁止输入 ACCEPTED 或 verifier_version。模型规划输出本身不能产生采信回执 |
| Evidence | 文档/主张/主体引用、支持/反证、片段和位置、关系核验版本、主体范围核验版本、主张级 origin_group、显式修订关系与限制 |
| Claim | 事实主张、当事方声明、分析估计、系统推断和假设分别标记；声明/估计需归属，推断需理由；状态及引用由有效证据投影，支持和反证同时存在时必须保留 CONFLICTING |
| Corroboration | 单独的语义独立性核验记录与理由；网站数/类别数/不同内容哈希不能自动生成独立印证 |

`accept_evidence` 是可信核验服务的入口，要求调用方提供独立的主体范围核验回执。它校验文档和主张 ID、主体相同、已分类且带哈希的文档、发布/获取日期，以及原文片段能在指定页段中定位。服务对语义判断的正确性仍依赖对应版本核验器；片段包含关系不是自动事实判定，也不以字符串版本号证明来源真实性。当前旧调查路径没有此主体范围回执，不能直接升级采信。

`EvidenceBundle` 在创建和持久化时校验整个引用图：重复/缺失 ID、非法主体引用、文档哈希不符、真实/合成/未知材料混用到同一主张、原文位置不符、主张状态与证据不符均拒绝。文本哈希校验重新计算全部 fragment 文本；原始响应字节哈希来自 P20 获取回执，不由文本抽取值冒充。该哈希标识内容，不保证材料真实性。

### 3. 时间、同源与修订

- 有效证据需发布日期已知且不晚于 as_of；已知事件/窗口与报告期间不越过截止日。获取时间允许晚于截止日，不能用抓取日替代发布/事件日。事后获取不等于截止日前已归档；动态页面没有历史版本证明时，仍需核验器披露限制。

## 5. 自然语言入口与 UI 最小闭环

入口层把用户 query、受限会话历史、可见任务摘要、工具目录、执行策略和预算快照交给结构化 LLM 决策，再由本地 Handler 与 Policy 校验。模型可回复、澄清、准备调查、提交澄清、查询状态或恢复调查；页面按钮继续直接调用已有工具。会话预算与调查预算分开控制，真实调用不会由界面隐式扩大授权。

入口普通对话仍经过事实引用门禁。若模型在闲聊中附带未引用的任务、企业、财务或报告事实，运行时移除这部分并返回安全的普通回复，不额外调用模型；用户明确询问这些事实时仍必须经工具和引用回答，不能用降级绕过。入口 Prompt、请求配置和对话版本均持久化，版本变化后旧会话不会静默续用不兼容配置。

## 6. 最小财务扩展与报告引用

深化 Case 使用 2025 年及 2024 年比较数据，截止日为 2026-04-02。金额统一为千元并保留年报原始定位，合并净利润与归母净利润分开；现金利润比只使用经营现金流/合并净利润，分母非正、字段缺失、期间或口径不匹配时返回不可计算。Decimal 保留计算精度，展示增长率和比率使用百分比两位小数，增速差表述为百分点。

财务计算结果写入可追溯 Artifact，并由报告引用实际期间、比较期间、公式版本、输入字段和原文片段。计算成功不自动回答调查问题；完成仍要求有效证据、模型语义评估和当前引用共同通过门禁。报告状态保持 `NOT_REVIEWED`，不得将模型推断或企业声明升级为审核事实。

## 7. 复杂案例回放与质量验证

冻结评测包位于 `evals/suites/byd_cash_quality_v2.json`，业务实现位于 `app/evals/complex_case_replay.py`，测试位于 `tests/test_v2_complex_case_replay.py`。命令入口为 `python -m app.eval_cli complex-case-replay --include-baseline`。这些名称描述功能，不再携带工作包编号。

同素材回放覆盖固定单轮基线和动态 agentic 调查，检查财务正确性、证据来源、实体范围、主张引用、报告缺口、预算计量和 UI 结果索引。真实模型试跑使用单独授权池，搜索和抓取保持离线；一次技术 PASS 只能证明链路能够产出候选，不能掩盖其他轮次的提前结束、遗漏 finding、重复核验或无报告。最终质量仍按五项等权 0–5 分、均分至少 4 分及硬失败规则由人工审核。

## 8. 验证与剩余边界

历史节点的测试轮次、真实调用用量、故障窗口和适应性修改详见开发日志及开发计划对应章节。命名与文档归并后，首轮全量为 623 项通过、5 项失败：1 项旧默认断言遗漏清理进程环境变量，1 项旧入口断言未适配普通对话安全降级，3 项 UI 测试受到用户已启用入口策略的环境影响。测试显式隔离相关环境输入并更新安全降级断言后，87 项定向回归全部通过。

最终 `scripts/verify.ps1` 通过 Ruff lint、220 个 Python 文件格式检查、628 项 pytest（477.48 秒）、依赖一致性和独立 MCP stdio smoke；MCP 路径为 `document → financial → research → risk`，research 状态为 `COMPLETE`。唯一警告是第三方 Traceloop 的既有 Pydantic 弃用提示。测试没有修改用户 `.env`，也没有调用真实模型、搜索或抓取服务。真实模型稳定性、正式人工评分、G2 批准以及后续 V2-3 财务深度不因离线回归通过而自动完成。
