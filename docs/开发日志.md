## 2026-08-12 — Day 0 Durable Execution Technical Spike

- **对应阶段：** Day 0 — Checkpoint / Interrupt / Kill Process / Resume。
- **文档原约定：** 使用 `node_a → interrupt() → 退出进程 → Command(resume) → node_b` 的最小流程，验证 SQLite Checkpoint、相同 `thread_id` 跨进程恢复，以及恢复后不重新执行已完成节点。
- **实际情况：** LangGraph 在 Resume 时会从包含 `interrupt()` 的节点开头重新执行。若 `node_a` 自身包含 interrupt，无法清晰区分“中断节点按框架语义重新进入”与“中断前已完成节点被错误重复执行”。
- **修改内容：** Spike 调整为 `prepare → approval(interrupt) → complete` 三节点流程；由 `prepare_runs` 记录 interrupt 前已完成节点的执行次数，并通过独立 Python 子进程分别执行 start、status 和 resume。
- **修改原因：** 在遵守 interrupt 节点无副作用约束的同时，准确验证已完成节点不会在跨进程 Resume 后重新执行。
- **影响范围：** 仅影响 Day 0 Spike 的验证结构，不改变后续业务 Graph、MVP 范围或验收目标。
- **验证结果：** SQLite 成功保存线程 Checkpoint；新进程使用相同 `thread_id` 恢复后任务进入 `COMPLETED`，且 `prepare_runs` 保持为 `1`；跨进程自动化测试共 2 项通过。

## 2026-08-12 — Day 1 Core Business Flow

- **对应阶段：** Day 1 — Financial → Risk → Report 最小业务纵向链路。
- **文档原约定：** Risk Agent 和固定模板报告由 LLM 生成表达，并通过 Pydantic Schema 约束结果。
- **实际情况：** 当前尚未配置可供自动化测试使用的模型凭证；若把外部模型调用作为 Day 1 门禁，核心财务公式、Schema 和纵向流程将无法离线稳定回归。
- **修改内容：** 保留外置 Risk/Report Prompt，并先实现确定性的结构化 Risk 基线与固定 Markdown 报告渲染器；财务计算仍全部由 Python Tool 执行。Risk 与 Report 通过独立函数边界提供，后续接入模型适配器时不改变 Financial Tool 和 Pydantic 数据契约。
- **修改原因：** 使 Day 1 纵向链路在无模型凭证情况下可重复测试，同时避免 LLM 参与确定性计算。
- **影响范围：** Day 1 的风险解释和报告文本暂为确定性基线；不影响后续动态路由、Artifact、HITL 或模型接入设计。
- **验证结果：** 两个固定 Case 均完成 Financial → Risk → Report；财务公式、缺失字段、年份顺序和零分母边界测试通过；Risk Pydantic 约束和固定报告章节测试通过；包含 Day 0 回归在内共 14 项测试通过。

## 2026-08-12 — 基础模型连接配置

- **对应阶段：** Day 1 — 配置与 Schema。
- **文档原约定：** 模型配置包含 `MODEL_NAME` 和 `MODEL_API_KEY`。
- **实际情况：** 用户需要自行配置兼容 OpenAI 调用方式的 API Base URL、模型名称和 API Key，以支持非默认模型服务端点。
- **修改内容：** 新增 `MODEL_BASE_URL`，与既有 `MODEL_NAME`、`MODEL_API_KEY` 组成模型连接配置；配置 Schema 提供 OpenAI 默认 Base URL，并将 API Key 读取为自动脱敏的 `SecretStr`，同时增加环境变量加载测试。
- **修改原因：** 允许在不修改应用代码的情况下切换兼容 OpenAI API 的基础模型服务。
- **影响范围：** 仅扩展模型连接配置，不改变当前财务计算、风险 Schema 或报告契约。
- **验证结果：** 环境变量中的 Base URL、模型名称和 API Key 均可正确加载，API Key 在配置对象中以 `SecretStr` 脱敏；包含既有回归在内共 15 项测试通过。
