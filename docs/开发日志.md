## 2026-08-12 — Day 0 Durable Execution Technical Spike

- **对应阶段：** Day 0 — Checkpoint / Interrupt / Kill Process / Resume。
- **文档原约定：** 使用 `node_a → interrupt() → 退出进程 → Command(resume) → node_b` 的最小流程，验证 SQLite Checkpoint、相同 `thread_id` 跨进程恢复，以及恢复后不重新执行已完成节点。
- **实际情况：** LangGraph 在 Resume 时会从包含 `interrupt()` 的节点开头重新执行。若 `node_a` 自身包含 interrupt，无法清晰区分“中断节点按框架语义重新进入”与“中断前已完成节点被错误重复执行”。
- **修改内容：** Spike 调整为 `prepare → approval(interrupt) → complete` 三节点流程；由 `prepare_runs` 记录 interrupt 前已完成节点的执行次数，并通过独立 Python 子进程分别执行 start、status 和 resume。
- **修改原因：** 在遵守 interrupt 节点无副作用约束的同时，准确验证已完成节点不会在跨进程 Resume 后重新执行。
- **影响范围：** 仅影响 Day 0 Spike 的验证结构，不改变后续业务 Graph、MVP 范围或验收目标。
- **验证结果：** SQLite 成功保存线程 Checkpoint；新进程使用相同 `thread_id` 恢复后任务进入 `COMPLETED`，且 `prepare_runs` 保持为 `1`；跨进程自动化测试共 2 项通过。
