用户已确认主张核验沿用 Coordinator 的模型尝试次数预留、Token 预留和输出上限，计入同一运行授权的总预算。工具派发前同时预留请求与 Token；返回用量完整时据实结算，未知时保守保留预留，已发生结果不会自动重新请求。CLI 为本次授权限制模型重试次数，原 settings 和 baseline 配置不改。

P22 网关独立启用两段用量汇总，记录包括无效输出、重试和失败的实际请求数；Usage 完整时汇总所有段的输入/输出 Token，否则保守保留 Token 预留。JSON 段显式 `enable_thinking=false`、`response_format=json_object` 并完成 JSON/Schema 校验；thinking 输出和 JSON 输出分别遵守授权上限。baseline 原请求和 accounting 返回语义保持兼容。恢复时若工具请求配置增加到超过持久化预留，则停止新派发，不拿旧预算发送新增请求。

本轮没有真实模型、搜索或 HTTP 调用。独立控制资料全部标记 SYNTHETIC；旧比亚迪、上汽案例保持原状。P24 财务计算、P23 复杂真实案例包及联合评测继续按计划后续实施。

## 2. 调查链路

- `read_document` 按证据 Artifact 和 document_id 选择单份原文，最多返回 8000 字符，明确标记截断和非可信输入。元数据、摘要与网址不冒充原文。
- `fetch_content` 在抓取前检查来源标签权限；保留原材料，新增正文哈希为 EXTRACTED_TEXT 的文档，不冒充原始响应字节，也不自动建立修订关系。HTTP 预留最大重定向请求数量，用量未提供逐请求回执时保守结算。P22 HTTP 拒绝跨主机重定向，baseline 保留原行为。
- `verify_claim` 使用同一授权限额的结构化模型，区分支持、反证、无关、不足、实际法人主体和来源依赖。模型不输出采信标记、核验版本或哈希；运行时校验提供给模型的原文引用、实体引用及证据图后创建核验回执。
- 新增 MCP `search_candidates`：一次检索只返回候选，不隐式抓取正文或调用旧核验器。原 `search_evidence`、company/industry baseline 协议保持原行为。生产 agentic Adapter 使用新通道；既有离线注入 Client 保持兼容。
- 模型可提出不可变 ID 的 ClaimProposal，绑定已知问题；主体和 REAL/SYNTHETIC 类型由运行输入、材料确定。假设不直接成为事实，同一 proposal_id 不能改写为其他断言。

核验汇合运行中已有全部证据；选择部分文档不能删除旧反证。独立印证需要模型明确提出语义一致与独立来源，并通过不同来源组、发布者及哈希的结构门禁；转载依赖和未知来源不能凭网站数量升级。

## 3. 重规划与完成门禁

Graph 和独立 Coordinator 均向模型提供证据索引、原文读取记录、主张状态及冲突。模型上下文视图限制为 18000 字符，并标记裁剪；运行时完成判定读取完整索引，不因裁剪遗漏历史反证。原始全文和完整证据图保存在 Artifact。

FINISH 的 QuestionAssessment 必须给出问题、公开结论、主张 ID、当前证据 Artifact 和局限。ANSWERED 仅接受同主体、同截止日、当前版本的 SUPPORTED/REFUTED 主张及有效原文证据。UNVERIFIED 或 CONFLICTING 主张不能完成问题；旧 SUPPORTED Artifact 不能遮盖后续冲突。该门禁校验引用与状态，是否回答了问题仍由模型进行语义判断，结构化计数不替代语义核验。

最新可信证据状态用于更新已有主张冲突；未知旧冲突 ID 保留。停止和评估结果分别落盘，计划、Action、模型返回、证据侧车、Observation 与预算可重放。重复取得同一 novelty_key 不算新进展。

`start_agentic_task(initial_evidence_bundle=...)` 支持显式导入同主体、同截止日的材料种子，为 P23 离线案例联通保留入口；本阶段不新建可运行真实 Case。

## 4. 验证与实际限制

定向控制已验证：充分证据走 read→verify→完成；存在澄清反证时走 read→verify→read→verify→独立检索→披露冲突。两个控制使用当前上下文选择行动，未用固定动作列表代替重规划。

另覆盖错误实体、虚构原文、截止日/缺失发布日期、不可变提案、伪造采信字段、同源转载与独立印证、局部核验保留反证、旧引用拒绝、未知用量、重试失败、抓取前权限、正文截断、跨主机重定向，以及核验三个崩溃窗口和派发前预算不足。新候选 MCP 经过真实协议的离线验证，禁止创建下游抓取和核验服务。

标准脚本通过 Ruff lint、182 个 Python 文件 format、370 项 pytest（137.14 秒）、pip check 和独立 MCP stdio smoke。全量脚本启动后补充的回执保留修复经过 P22 与旧 MCP 通道定向验证，26 项通过（8.88 秒，包含 22 项 P22 控制）；最终 lint/format 和 diff 检查通过。仅有第三方 Traceloop 既有 Pydantic 弃用警告。

两段请求确认后的最终标准脚本通过 Ruff lint、184 文件 format、379 项 pytest（133.52 秒）、pip check 和独立 MCP stdio。新增网关控制覆盖两段、各段重试、摘要失败后的 JSON 校验、JSON 重试耗尽、用量未知和输入预检零请求；预算控制覆盖两段共享总预算及核验前预留不足。全量脚本启动后补充的恢复配置保护，经 P22/旧恢复定向 42 项通过（35.40 秒，含 25 项 P22 控制）。完整实施过程见开发日志。

P22 固定模型只验证契约、动态路径和保护机制，不证明真实 LLM 的调查质量。P23 尚未进行同素材 baseline 对照或五项评分，不能据此宣称 G2 通过。

生产检索的旧 Schema 没有可信来源分类及原始发布者回执。此类输入保持未知，不从模型输出或网站数量补齐；存在来源限制时不能直接读取/抓取未知分类。后续 P23 使用已冻结且带可信分类的材料种子；扩展实时渠道分类需要另行确定映射。CLI 的 `--evidence-source-kind` 只声明真实/合成类型，不授予来源权限。API 注入模型的调用方须遵守授权尝试次数，并如实提供请求/Token 预留倍数及实际请求用量；CLI 的保护不自动约束任意第三方注入模型。
